## Конфиденциальность

Приложение хранит ровно две вещи, обе — в своей **закрытой** памяти, которую другие приложения прочитать не могут:

1. `settings.xml` — ваш выбор в настройках (язык, размеры, цвета…).
2. `current_game.json` — текущая партия, чтобы её можно было продолжить после закрытия приложения. Файл удаляется, когда партия закончена или прервана.

Если вы включили встроенное резервное копирование Android, система может включить эти два файла в *вашу* резервную копию Google (и в перенос данных с телефона на телефон), чтобы на новом телефоне сохранились ваши настройки. Это задано в файлах [`backup_rules.xml`](../../app/src/main/res/xml/backup_rules.xml) и [`data_extraction_rules.xml`](../../app/src/main/res/xml/data_extraction_rules.xml). Больше ничего никогда не сохраняется и никуда не отправляется.

Кнопка «Открыть страницу проекта» в разделе Настройки → О приложении просто просит Android открыть страницу GitHub в вашем браузере; само приложение по-прежнему ни с чем не соединяется.

## Разрешения

В [манифесте](../../app/src/main/AndroidManifest.xml) **нет ни одного** `<uses-permission>`. Это можно проверить на любом APK с помощью Android SDK:

```bash
aapt2 dump permissions MiliGames-v1.0.0.apk
```

Вы увидите одну-единственную запись, которая заканчивается на `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. Это не разрешение для пользователя: это внутреннее разрешение уровня подписи, которое библиотека AndroidX добавляет автоматически, чтобы защитить внутренние приёмники сообщений самого приложения от других приложений. Оно никому ничего не даёт.

Без разрешения `INTERNET` Android вообще не позволяет приложению открывать сетевые соединения.

## Что внутри приложения

Полный список зависимостей находится в [`gradle/libs.versions.toml`](../../gradle/libs.versions.toml):

| Библиотека | Издатель | Зачем |
|---|---|---|
| `androidx.activity:activity-compose` | Google (AndroidX) | Показывает интерфейс Compose внутри activity |
| `androidx.compose.ui`, `foundation`, `material3` | Google (AndroidX) | Набор инструментов для интерфейса |
| `org.jetbrains.kotlinx:kotlinx-serialization-json` | JetBrains | Сохранение текущей партии в формате JSON |
| Стандартная библиотека Kotlin | JetBrains | Среда выполнения языка |

Библиотеки только для тестов (в приложение никогда не попадают): JUnit, Robolectric, Compose UI test.

В приложении **нет картинок, звуков, шрифтов и нативных библиотек**: каждый рисунок нарисован кодом, который можно прочитать в [`ui/art`](../../app/src/main/java/io/github/fershibli/megagames/ui/art). Единственные файлы с данными — словари кроссворда в виде обычного текста ([`assets/crossword`](../../app/src/main/assets/crossword)).

В выпускной сборке также отключён блок Google «dependency info» (`dependenciesInfo { includeInApk = false }`) — зашифрованные данные, которые иначе были бы встроены в APK. Поэтому каждый байт APK можно изучить.

## Как проверяется код

При каждом изменении и каждом pull request в GitHub Actions запускается [CI](../../.github/workflows/ci.yml):

1. **Проверка Gradle wrapper** — подтверждает, что `gradle-wrapper.jar` — официальный файл.
2. **50 автоматических тестов**, среди них:
   - правила каждой игры (разрешённые ходы, подсчёт очков, выбрасывание шашек, комбинации и джокеры в бурако…);
   - генераторы: у каждого судоку единственное решение, каждая раскладка маджонга решаема, у каждой головоломки «Трубы» и «Соедини цвета» есть полное решение, слова в кроссворде никогда не конфликтуют;
   - соперники-компьютеры быстро доигрывают партии и никогда не теряют и не удваивают карту или шашку;
   - все девять языков переводят каждый текст и сохраняют одинаковые подстановки;
   - сохранение и восстановление партии, обработка повреждённого сохранения, сохранение настроек;
   - настоящий интерфейс: включение и выключение масштаба двумя пальцами, масштаб одной рукой двойным касанием и нажатием с вращением, выбор игры, выход из неё через настройки и вопрос «Продолжить?» после перезапуска.
3. **Android Lint**, где *предупреждения считаются ошибками*.
4. **Сборка** отладочного и выпускного APK, которые публикуются как артефакты с **контрольными суммами SHA-256**.

Те же проверки можно запустить самостоятельно: см. [building.md](../en/building.md) (на английском).

## Проверка скачанного APK

1. Скачайте `MiliGames-vX.Y.Z.apk` и `SHA256SUMS.txt` из одного и того же [выпуска](https://github.com/fershibli/game-mega-app/releases).
2. Вычислите контрольную сумму и сравните:

   ```bash
   sha256sum MiliGames-vX.Y.Z.apk      # Linux / macOS: shasum -a 256
   certutil -hashfile MiliGames-vX.Y.Z.apk SHA256   # Windows
   ```

3. Убедитесь, что сертификат подписи не меняется от версии к версии (к тому же Android откажется обновлять приложение, подписанное другим ключом):

   ```bash
   apksigner verify --print-certs MiliGames-vX.Y.Z.apk
   ```

4. Для полной уверенности соберите APK сами из исходного кода с нужной меткой версии и сравните содержимое (`unzip -l`, `aapt2 dump badging`).

## Защита цепочки поставок

- `distributionSha256Sum` закрепляет точную версию Gradle в [`gradle-wrapper.properties`](../../gradle/wrapper/gradle-wrapper.properties).
- Зависимости загружаются только из репозитория Maven от Google и из Maven Central (`repositoriesMode = FAIL_ON_PROJECT_REPOS`).
- [Dependabot](../../.github/dependabot.yml) каждый месяц предлагает обновления зависимостей и GitHub Actions.
- CI работает с правами только на чтение; записывать могут только процессы нумерации версий и публикации, и только для того, чтобы поставить метку версии и опубликовать выпуск. Процесс работы с ключом подписи записывает только секреты подписи, используя токен, который имеет доступ лишь к секретам этого репозитория.
- Каждый публикуемый APK проверяется до загрузки: подпись (`apksigner`), название версии и отсутствие запрашиваемых разрешений (`aapt2`).
- Ключи подписи выпусков хранятся в зашифрованных секретах GitHub и никогда не попадают в репозиторий (`*.jks` и `keystore.properties` исключены через git-ignore).

## Честно о помощи ИИ

Код, рисунки и документация созданы с помощью **Claude**, ИИ-ассистента компании Anthropic, под руководством автора проекта. В коде, написанном ИИ, как и в любом другом коде, могут быть ошибки. Поэтому проект опирается не на обещания, а на то, что можно проверить: понятный исходный код, широкий набор тестов, линтер, воспроизводимую сборку и опубликованные контрольные суммы. Если вы заметите проблему, пожалуйста, сообщите о ней.

## Как сообщить о проблеме безопасности

См. [SECURITY.md](../../SECURITY.md). Пожалуйста, не открывайте публичный issue об уязвимости; воспользуйтесь закрытой отправкой сообщений об уязвимостях на GitHub (private vulnerability reporting).
