## 技术选型

需求是：“尽量用 React Native，但请选择在体积、内存和处理器占用上最轻的方案；只做安卓”。比较如下：

| | React Native（Hermes） | Flutter | **Kotlin + Jetpack Compose** |
|---|---|---|---|
| 本应用的正式版 APK | 约 15–25 MB（每个 ABI 的 JS 引擎 + RN 核心） | 约 8–12 MB（每个 ABI 的引擎） | **约 1.3 MB**（实测） |
| 内存中额外的运行时 | JS 引擎 + 桥接 | Dart 虚拟机 + Skia/Impeller | 无（直接运行在 ART 上） |
| 绘制棋盘 / 双指缩放 | 需要额外的库（Skia、gesture handler、reanimated） | 内置 | 内置（`Canvas`、触摸输入） |
| 安卓原生无障碍（TalkBack、字体大小） | 通过桥接 | 自己实现 | 直接支持 |

*React Native 和 Flutter 的体积是小型应用的典型数值；本项目只实测了 Compose 的体积。*

**决定：** 原生 **Kotlin + Jetpack Compose**，单一 Activity，没有游戏引擎，没有图片资源。Compose 属于安卓平台库（AndroidX），经过 R8 精简后 APK 只包含真正用到的部分。实测正式版 APK 约 **1.3 MB**。

其他让应用保持小巧、易于审查的选择：

- 不用导航库：导航是一个只有四种状态的密封接口。
- 不用 DataStore/Room：设置用 `SharedPreferences`；唯一的存档是一个以原子方式写入的 JSON 文件。
- 不用图标字体或图片：图标和所有游戏画面都用 `DrawScope` 绘制。
- 最低支持 Android 6.0（API 23），照顾老年人常用的旧手机。

## 架构

```
MainActivity
 └─ MegaGamesApp（状态机：主界面 → 选择难度 → 游戏中，另有设置）
     ├─ MegaGamesTheme ── 配色（6 种）、语言、字体缩放、通过 CompositionLocal 提供设置
     ├─ HomeScreen / DifficultyScreen / SettingsScreen
     └─ GameScreen ── 顶栏 + 齿轮、游戏内设置、“继续吗？”和结束对话框
          └─ GameContent(游戏) ── 每款游戏一个 composable
               └─ LoadGame(host, serializer, create)   ← 恢复或生成状态，并自动保存每次变化
                    └─ GameLayout(状态栏, ZoomableBoard(棋盘), 控件)
```

每款游戏分为：

- **引擎**——纯 Kotlin，不依赖安卓，不可变的 `@Serializable` 状态，全部有单元测试；
- **界面**——Compose 界面，在 `Canvas` 上绘制状态，并把点击转换为对引擎的调用。

电脑对手在 `Dispatchers.Default` 上运行，界面永远不会卡住，并且会一步一步展示它的走法。

## 导航、设置与自动保存

- **导航** 是一个 `sealed interface Screen`。手机的返回键：设置 → 主界面，选择难度 → 主界面；在游戏中则打开/关闭游戏内设置（不会误离开一局游戏）。
- **设置** 是一个不可变的 `data class`，每次修改都写入 `SharedPreferences`，并通过 `CompositionLocal` 提供给整个界面。
- **自动保存**：`LoadGame` 把游戏状态放进 `MutableState`，并用 `snapshotFlow` 观察；每个新状态都会序列化成 JSON 交给 `SaveStore`。`SaveStore` 在一个后台线程上写入，*以最新的一次为准*，先写临时文件再重命名（崩溃也不会留下写了一半的文件）。`GameHost.finish()` 会删除存档，因此已结束的游戏不会再被提示继续。
- **“继续吗？”**：冷启动时（`savedInstanceState == null`），`MegaGamesApp` 读取存档并直接打开那局游戏，同时弹出询问。无法解析的存档（损坏或版本不兼容）会被忽略，并生成新游戏。
- Activity 自行处理配置变化（`android:configChanges`），所以旋转、折叠或切换深色模式都不会重建界面或丢失状态。

## 缩放与单手手势

`ZoomableBoard` 包裹所有棋盘。它在触摸事件的 **Initial** 阶段监听，比游戏更早收到事件：

- 两根或更多手指（开启*双指缩放*时）→ 以手指中心为基准缩放和拖动；这些事件会被消费，游戏不会收到误触。
- 一根手指 → 原样传给游戏；由于棋盘用 `graphicsLayer` 变换，游戏使用普通的本地坐标即可（Compose 会自动换算触摸坐标）。
- 单手*双击*：双击的第二下会被消费；单纯双击 = 逐级缩放（1× → 2× → 3× → 1×），双击后拖动 = 移动画面。
- 单手*按住旋转*：长按时间到达后（伴随震动），手指围绕按下点转动的角度控制指数式缩放（顺时针 = 放大）。双击恢复，双击后拖动移动画面。

拖动范围有限制，棋盘不会被拖出屏幕；放大时会出现恢复按钮。

## 不用图片的美术

所有画面都在运行时用 Compose 的 `DrawScope` 绘制，因此在任何缩放下都清晰，并且会随六种配色自动变色：

- **立体感**：`raisedBlock()` 由浅到深绘制几层侧面，再加一个渐变的正面（麻将牌、骰子）；`glossyDisc()` 绘制阴影、径向渐变、边棱和高光（双陆棋子、黑白棋子、圆点）；扑克牌带有多层柔和阴影。
- **扑克牌**：花色是矢量路径；点数在上方两个角都放得很大，即使牌叠在一起也能看清；人头牌带有皇冠；色盲友好配色使用四色牌；法语使用 R/D/V 表示 K/Q/J。
- **麻将**：筒子、条子（一条是传统的小鸟）、万子（汉字数字 + 萬）、风牌、箭牌、花牌和季节牌，角上另有阿拉伯数字索引。
- **配色**：普通、高对比度和色盲友好（Okabe–Ito），各有浅色和深色版本。在无障碍配色中，每个彩色棋子上还会画出形状（`drawSymbol`）。

## 题目生成器

| 游戏 | 方法 | 保证（有测试） |
|---|---|---|
| 数独 | 用回溯随机生成完整盘面；按随机顺序逐个移除数字，只有当解计数器（按最受约束格回溯，数到 2 即停）仍然只找到一个解时，才保留这次移除。 | 唯一解；各难度的提示数 |
| 麻将 | 固定布局（塔形 48、城堡 96、竖放的乌龟 144）。通过*倒着模拟游戏*来分配牌面：反复取出当时可选的两个位置，给它们一对相同的牌。按这个顺序玩就能赢。洗牌时对剩下的牌重复这个过程。 | 每次发牌和每次洗牌都可解 |
| 接水管 | 从中央水源出发生长的随机生成树（随机 Prim 算法，避免四通管），然后把每节管子随机旋转。 | 连通、无回路、可解；开局绝不是已解状态 |
| 颜色连线 | 一条走遍棋盘的哈密顿路径（蛇形），经过数千次“backbite”变换随机化，再切成长度至少 3、两端不相邻的彩色段。 | 可以在填满整个棋盘的情况下解开 |
| 填字游戏 | 先放长词；新词只能放在与已有字母交叉的位置，且不能从侧面贴着其他词；最多尝试 60 次取最佳；像印刷版一样编号。 | 字母不冲突；各难度的词数 |
| 点点消除 | 随机颜色；下落后补充新点；如果没有可走的步就重新打乱。 | 总有可走的步 |
| 纸牌接龙 / 巴西拉米 | 一副 / 两副牌的公平洗牌（`kotlin.random`）。 | — |

## 电脑对手

按照需求，首先考虑了现成的引擎：

- **GNU Backgammon** 是权威的开源双陆棋引擎，但它用 C 语言编写、采用 GPL 许可，需要用 NDK 为每种处理器编译，会增加数 MB 体积，并迫使整个应用采用 GPL。
- **巴西拉米** 没有成熟的开源引擎（只有个人项目和论坛讨论）。

因此电脑对手是专门为本应用用纯 Kotlin 编写的：

**黑白棋**——带 Alpha-Beta 剪枝的极大极小搜索。评估：位置权重表（角 +100，角旁边的格 −20/−50）、行动力，以及残局时的棋子数。简单：搜索 1 层，35% 的概率随机落子。中等：搜索 3 层（残局 8 层）。困难：搜索 6 层，并对最后 12 个空格进行完全搜索（完美残局）。

**双陆棋**——完整的走法生成（从中间栏进场、打子、按“大骰子规则”移出、必须“用满两个骰子 / 用大的那个”的规则），基于各自视角的棋盘表示。评估：点数（pip）差、按重要性加权的已占点、封锁长度、锚点、根据 36 种骰子结果中能打中单子的数量估算的暴露风险、中间栏上的棋子，以及脱离接触后单独的赛跑评估。简单：45% 的时间随机走。中等：选择自己走完后评估最好的走法。困难：取最好的 5 个候选，再多看一步，对对方 21 种可能骰子结果的最佳应对取平均（期望极大极小）。

**巴西拉米**——启发式玩家：判断是否拿弃牌堆（最上面的牌能否立即使用、整个弃牌堆的价值），优先放出天然顺子，往已有顺子里加牌，按难度使用百搭牌（困难模式会保持干净的卡纳斯塔），并弃掉“保留价值”最低的牌（手中相邻的牌、能否接到自己的顺子），再加上“危险成本”——能接到你顺子上的牌、或与你拿过的牌相近的牌会被避免弃出。

电脑对电脑，由 `AiBenchmarkTest`（可选运行）生成：

## 国际化

- 界面文字在 `res/values/strings.xml`（英语）以及 `values-pt`、`values-es`、`values-fr`、`values-zh` 中。
- 应用内切换语言时，会用 `createConfigurationContext` 创建的上下文包裹整个 Compose 树，因此不依赖 AppCompat，在所有安卓版本上都可用。在 Android 13+ 上，这些语言也会出现在系统的“按应用设置语言”中（`locales_config.xml`）。
- 只打包这五种语言（`localeFilters`），并关闭了应用包（App Bundle）的按语言拆分，所以切换语言永远不需要下载。
- 填字词库是纯文本：`答案|提示`。答案会被规范化（大写、去掉重音符号、西班牙语保留 Ñ、Œ → OE）；中文每个汉字占一格。
