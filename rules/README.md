# Regras de qualidade

Cada regra existe porque algo deu errado (ou quase) na história do projeto. O "porquê" vem junto, para que a regra seja entendida e não só seguida.

| Arquivo | Assunto |
|---|---|
| [01-git-e-prs.md](01-git-e-prs.md) | Branches, commits, PRs, merge e autoria |
| [02-produto.md](02-produto.md) | O público (pessoas idosas) e o que o app nunca faz |
| [03-codigo.md](03-codigo.md) | Arquitetura, salvamento, desempenho, dependências |
| [04-textos-e-idiomas.md](04-textos-e-idiomas.md) | Os 10 idiomas, "Aprenda a jogar", dicionários |
| [05-testes-e-ci.md](05-testes-e-ci.md) | Testes, CI e como diagnosticar falhas |
| [06-visual-e-acessibilidade.md](06-visual-e-acessibilidade.md) | Desenho, cores, toque, modos de exibição |
| [07-pronto.md](07-pronto.md) | Checklist de "pronto" antes de pedir o merge |

**Prioridade em caso de conflito:** pedido explícito da dona do produto > `rules/` > `backlog/HANDOFF.md` > costume do código existente.

**Palavras:** "deve" e "nunca" são obrigatórios; "prefira" é o padrão, que pode ter exceção justificada no PR.
